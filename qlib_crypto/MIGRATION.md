# qlib -> qlib-crypto Migration Guide

This guide describes how to migrate an existing qlib stock workflow to crypto workflow.

## 1) Initialization

Stock:

```python
qlib.init(provider_uri="~/.qlib/qlib_data/cn_data", region="cn")
```

Crypto:

```python
qlib.init(provider_uri="~/.qlib/crypto_data", region="crypto")
```

## 2) Data preparation

Use crypto collector + pipeline:

```bash
python scripts/data_collector/crypto_ohlcv/collector.py download_data \
  --source_dir ~/.qlib/crypto_ohlcv/source/1d \
  --exchange binance --quote_asset USDT --interval 1d

python scripts/data_collector/crypto_ohlcv/collector.py normalize_data \
  --source_dir ~/.qlib/crypto_ohlcv/source/1d \
  --normalize_dir ~/.qlib/crypto_ohlcv/normalize/1d --interval 1d

python -m qlib_crypto.data.pipeline \
  --normalize_dir ~/.qlib/crypto_ohlcv/normalize/1d \
  --qlib_dir ~/.qlib/crypto_data --exchange binance --freq day
```

## 3) Data handler replacement

- `Alpha158` -> `Alpha158Crypto`
- optional `label_mode="perp_funding_adj"` for perp-style label adjustment

## 4) Strategy replacement

- `TopkDropoutStrategy` -> `CryptoTopkStrategy`

## 5) Exchange constraints

Use crypto-specific constraints in exchange kwargs:

- `min_qty`
- `qty_step`
- `min_notional`
- `price_tick`
- `max_volume_ratio`

## 6) Optional custom ops

Register crypto ops in `qlib_init.custom_ops`:

- `FundingZScore`
- `BasisPct`
- `OIRatio`


## 7) 7*24 and no T+1 reminders

- Use continuous calendars (`day` and/or `1min`) generated by qlib_crypto tools.
- Set strategy `hold_thresh: 0` for crypto to avoid T+1 style hold constraints.
- Keep `limit_threshold: null` in exchange kwargs for crypto markets.
